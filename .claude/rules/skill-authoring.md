## Skill Authoring

- Do not set `disable-model-invocation: true` in SKILL.md frontmatter unless the user explicitly asks for it. This Claude extension blocks native skill orchestration there. If it appears on an existing skill, ask before keeping it. Shared workflows must also work when invoked by reading their SKILL.md in a harness without a native skill tool.
- **Load context explicitly.** List the shell commands the agent must execute before interpreting their output. Use `bash ~/.agent-skills/scripts/<skill>/context.sh <flag>`; shared workflows must not depend on Claude-only dynamic shell interpolation.
- **Use shared resources and configuration.** Resources live under `~/.agent-skills/skills/<skill>/`, commands under `~/.agent-skills/scripts/<skill>/`, and common settings in `~/.agent-skills/config.json`. Resolve scripts/resources through their real source paths rather than lexical parents of installed symlinks. Preserve the documented legacy fallbacks and explicit config override.
- **Declare support honestly.** Maintain each skill's `supportedAgents` array in `skills/compatibility.json`. Keep generic workflow logic shared; isolate actual harness/tool adapters. Claude frontmatter extensions may remain, but Codex must not rely on their execution.
- **Use active capabilities.** Follow `skills/shared/references/harness-capabilities.md` for native skill invocation, questions, progress, delegation, worktrees, and service tools. Map low/medium/high model and effort tiers to the active harness's available choices; do not hard-code another provider's identifiers.
- **Deterministic work should be scripts, not AI.** If a step has no judgment calls (file I/O, shell commands, version lookups), make it a Python or shell script. Shell entry points use the installer-selected Python interpreter. The AI handles interviews, diagnostics, and customizations.
- **Use the current question schema.** Inspect the available question tool's constraints instead of assuming another harness's fields or option counts. Plain questions are valid when no suitable tool is available. Never construct choices from dynamic data without checking the supported count; skip a redundant question when only one meaningful choice exists.
- **Keep dependent questions sequential.** A batch presents all questions at once. If question B depends on question A, wait for A before asking B.
